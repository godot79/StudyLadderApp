## Working Style
- Be concise
- Keep output short and practical
- Do one step at a time
- Do not overengineer
- Do not make broad changes unless asked
- Do not code until the task explicitly asks for coding
- State assumptions briefly
- If something is unclear, ask or flag it instead of guessing

## Build Strategy
- Prefer the smallest safe step
- Work in vertical slices
- Align to documented scope
- Do not add future-facing complexity unless needed now

## Output Format
For implementation tasks, respond with:
1. What I changed
2. Commands run
3. Files created/changed
4. Any issues

## Rule
If a requested change conflicts with the documented scope, flag it before proceeding.
